# Кабинет мастера Ясна

Рабочий прототип для компьютера и браузера телефона. HTML формируется Django.
Формы отправляются обычным POST, фильтры и навигация используют GET.
Клиентский JavaScript отсутствует.

## Запуск на Windows

Дважды нажмите start.cmd. При первом запуске создаётся виртуальное окружение,
устанавливаются зависимости, применяются миграции и добавляются вымышленные данные.
Если учётной записи мастера ещё нет, программа предложит создать её.
После запуска откройте http://127.0.0.1:8000.

Python 3.12 должен быть установлен и доступен командой python.
Для остановки сервера нажмите Ctrl+C в его окне.

## Ручной запуск

Из папки master_portal выполните команды.

~~~powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -X utf8 manage.py migrate
.venv\Scripts\python.exe -X utf8 manage.py demo_data
.venv\Scripts\python.exe -X utf8 manage.py createsuperuser
.venv\Scripts\python.exe -X utf8 manage.py runserver
~~~

Доступ к кабинету есть у активных пользователей Django с is_staff=True.
Учётные записи, база и загруженные чеки создаются локально.

## Что работает

- Расписание по дням, переход между неделями и фильтр по формату.
- Создание и редактирование групповых и индивидуальных занятий.
- Одно общее задание и список материалов на занятие.
- Запись ребёнка, защита от дублей и превышения вместимости.
- Перенос активной записи с проверкой мест в новой группе.
- Посещаемость, списание по правилам, исправление и возврат занятия.
- Отмена занятия мастером с возвратом списаний.
- Ученики, родители, остатки абонементов и поиск.
- Ручные оплаты наличными и переводом, выдача абонемента.
- Повторная отправка той же формы оплаты не выдаёт второй абонемент.
- Прикрепление чека по HTTPS-ссылке или файлом PDF, PNG, JPG.
- Скачивание файлов чеков через проверку доступа мастера.
- Версии правил отмен, история изменений и уведомления мастера.
- Экспорт учеников, посещений и оплат в CSV.
- Мобильный журнал перед списком занятий, нижняя навигация, крупные кнопки.

## PostgreSQL

По умолчанию для быстрого локального просмотра используется SQLite.
Для PostgreSQL задайте параметры перед migrate и запуском сервера.

~~~powershell
$env:POSTGRES_DB = "yasna"
$env:POSTGRES_USER = "yasna"
$env:POSTGRES_PASSWORD = "ваш-пароль"
$env:POSTGRES_HOST = "127.0.0.1"
$env:POSTGRES_PORT = "5432"
.venv\Scripts\python.exe -X utf8 manage.py migrate
.venv\Scripts\python.exe -X utf8 manage.py demo_data
.venv\Scripts\python.exe -X utf8 manage.py createsuperuser
.venv\Scripts\python.exe -X utf8 manage.py runserver
~~~

База PostgreSQL и её пользователь создаются заранее. Данные из SQLite
автоматически в PostgreSQL не переносятся.

Для публичного сервера задайте DJANGO_DEBUG=0, DJANGO_SECRET_KEY,
DJANGO_ALLOWED_HOSTS, настройте HTTPS, сервер приложения и раздачу static.
Каталог private-receipts должен оставаться закрытым от прямого веб-доступа.
Сервер runserver предназначен для локальной разработки.

## Структура и подключение к общей архитектуре

- dashboard/templates/dashboard — HTML-шаблоны кабинета и входа.
- dashboard/static/dashboard — CSS и изображения.
- dashboard/forms.py — валидация серверных форм.
- dashboard/views.py — страницы, POST-обработчики, CSV и доступ к чекам.
- dashboard/services.py — операции записи, посещений, оплаты и исправлений.
- dashboard/models.py и migrations — самостоятельная демонстрационная модель.
- config/settings.py — окружение и выбор базы.

Этот каталог можно запускать отдельно, пока участник 1 готовит общий каркас.
При интеграции команда переносит модели по приложениям accounts, scheduling,
billing, notifications и core согласно README ветки Andrey, затем обновляет
импорты в forms, services и views. Миграции прототипа используют префикс
dashboard_ и требуют согласования с общими миграциями перед объединением баз.

В модели занятия добавлено поле description для общего задания и материалов.
Временная модель уведомлений обслуживает кабинет мастера.
Семейный кабинет описан в FAMILY.md. Возвраты денег, свободные авансы
и производственная система резервного копирования остаются задачами общей системы. Форма оплаты в этом кабинете регистрирует
уже полученную ручную оплату.

Баланс абонемента вычисляется по движениям LessonEntry. Изменения отметок
сохраняются в AuditEvent. Операции используют transaction.atomic и блокировки
select_for_update. Проверку конкурентных запросов нужно запускать на PostgreSQL,
где работают блокировки строк.

## Проверка

~~~powershell
.venv\Scripts\python.exe -X utf8 manage.py check
.venv\Scripts\python.exe -X utf8 manage.py makemigrations --check --dry-run
.venv\Scripts\python.exe -X utf8 manage.py test dashboard
~~~

Проверены серверные тесты на SQLite и сценарий в Edge с отключённым JavaScript.
В браузере проверены создание занятия, запись, сохранение после обновления,
посещение с остатком 4 → 3, исправление 3 → 4, разделы кабинета и ширина 390 px.
PostgreSQL на машине разработки отсутствовал, проверка конкурентных запросов
на PostgreSQL ещё предстоит.
