# Ясна

Django-приложение для детской столярной мастерской. Мастер управляет расписанием, семьями, посещениями, оплатами и чеками. Родитель входит по персональной ссылке, управляет профилями детей и видит их занятия, остатки, чеки и уведомления.

[Руководство по функциям и уведомлениям](USER_GUIDE.md).

## Где продолжать работу

Рабочая ветка — `Andrey`. На другом аккаунте Codex откройте локальный каталог проекта или клонируйте ветку. Доступ к репозиторию должен быть у аккаунта GitHub, под которым выполняется Git.

```powershell
git clone --branch Andrey https://github.com/K-R-O-K-I/UgraCode.git
cd UgraCode
```

Git переносит код, миграции и шаблоны. Локальные настройки `.env`, база PostgreSQL и приватные файлы из `private_media/` хранятся отдельно. На том же ноутбуке с существующим клоном используйте уже настроенную БД и `.env`. На новой машине можно поднять чистую БД и заполнить её демоданными.

## Запуск с нуля

Нужны Python 3.14 и PostgreSQL 17. PostgreSQL запускается локально, например службой Windows. Docker для локального запуска не нужен.

В pgAdmin или psql подключитесь к базе `postgres` администратором и выполните по очереди, подставив свой пароль. Если база и роль уже существуют, используйте существующее подключение.

```sql
CREATE ROLE yasna WITH LOGIN PASSWORD 'ваш-локальный-пароль';
CREATE DATABASE yasna OWNER yasna;
```

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(50))"
```

В `.env` укажите сгенерированный `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD` и при необходимости остальные параметры подключения. Для локального запуска нужны `DJANGO_DEBUG=true` и хост `127.0.0.1` в `DJANGO_ALLOWED_HOSTS`. Для демонстрации оплаты добавьте `PAYMENT_MODE=demo`.

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py setup_master
# Только если нужны вымышленные семьи, занятия и тарифы для демонстрации:
.\.venv\Scripts\python.exe manage.py demo_data
.\.venv\Scripts\python.exe manage.py family_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

На Linux/macOS используйте `python3` для создания окружения и `.venv/bin/python` для остальных команд. После изменения `.env` перезапустите сервер. При ошибке подключения проверьте службу PostgreSQL, порт, пользователя и пароль.

Войдите в кабинет мастера на [127.0.0.1:8001](http://127.0.0.1:8001/) под учётной записью из `setup_master`. В разделе «Управление семьями» создайте или выберите семью и выдайте персональную ссылку. Откройте её в отдельном профиле браузера, чтобы проверить родительский кабинет. Родитель добавляет детей в разделе «Дети». Мастер прикрепляет готовый файл или ссылку на чек к конкретной оплате. Семья открывает чек в разделе «Оплаты и чеки».

## Где что находится

- `config/` — настройки, маршруты и подключение PostgreSQL.
- `accounts/` — семьи, дети, личные ссылки и защищённая выдача аватарок.
- `dashboard/` — кабинет мастера и действующие модели расписания, записей, абонементов и оплат. Бизнес-операции собраны в `dashboard/services.py`.
- `families/` — кабинет родителя, уведомления, оплата и создание записей. Шаблоны и стили находятся внутри приложения.
- `static/app.js` — отправка обычных Django-форм без полной загрузки страницы и сохранение прокрутки.
- `Архитектура/` — проектные материалы. Текущую структуру БД определяют Django-модели и миграции.

Деморежим имитирует оплату. После подтверждения записи создаются платёж, абонемент и бронь. Для ЮKassa предусмотрены `PAYMENT_MODE=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, публичный HTTPS-адрес `PUBLIC_BASE_URL` и webhook `/family/webhook/`. Реальные платежи не проверены. Оплата конкретной записи сейчас работает в деморежиме.

## Проверки перед коммитом

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

Django создаёт отдельную тестовую базу. Если роль разработки не может создавать БД, используйте отдельную локальную роль с `CREATEDB` через переменные `POSTGRES_USER` и `POSTGRES_PASSWORD` текущего процесса. GitHub Actions повторяет проверки на PostgreSQL 17.

Коммитьте миграции вместе с изменениями моделей. Храните `.env`, резервные копии, чеки, аватарки и персональные ссылки вне Git.

## Уведомление об одном оставшемся занятии

Когда суммарный остаток действующих абонементов ребёнка становится равен одному,
в разделе «Уведомления» его семьи появляется непрочитанное напоминание с именем ребёнка.
Оно создаётся при изменении остатка, например после отметки посещения, и не дублируется,
пока остаток равен одному. Если он изменился и затем снова стал равен одному,
семья получит новое уведомление. Для каждого ребёнка остаток проверяется отдельно.

После обновления выполните `manage.py migrate`. Команда `manage.py family_reminders`
может сверить уже существующие остатки и изменения из-за истечения абонементов.
Для регулярной сверки по датам запускайте её ежедневно через планировщик.
Она также проверяет сроки действия абонементов и открытые счета.


## Запись и отмена, обновление 15 ноября

Новая запись использует занятие с действующего на дату урока абонемента.
Если остатка нет, доступен существующий сценарий демооплаты.
Занятие списывается при записи, отметка посещения повторно его не списывает.
Своевременная отмена родителем возвращает занятие. Поздняя отмена требует
подтверждения и сохраняет списание. В обоих случаях освобождается место.
При отмене мастером активным участникам возвращается по одному занятию.
Повторные запросы отмены не создают повторных возвратов.
Старые записи учитываются отдельно от записей с предварительным списанием.

Вкладка «Сегодня» показывает текущий день и раскрывающиеся списки участников.
Вкладка «Расписание» используется для выбора даты, просмотра участников, создания и отмены занятий.
Редактирование созданного занятия, запись и перенос ребёнка мастером закрыты.
В разделе семей доступен поиск и просмотр профиля ребёнка.
После обновления требуется migrate, в том числе dashboard.0003_booking_prepaid.
